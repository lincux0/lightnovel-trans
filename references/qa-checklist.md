# 自检与 QA 清单

> 语义审核与机械检查相互补充。段落数相等、没有假名或长度比正常都不能证明翻译正确。只读审核不运行写入型转换、打包或渲染产物生成脚本。

## 一、语义与文风（每章）

- [ ] 事件、因果、否定范围、授受方向、指代与视角正确，无信息漏译或增写。
- [ ] 称呼符合说话人、对象和当前时间线，番外/回忆不误用后期关系。
- [ ] 惯用语、双关、特殊 ruby、外字、图中文字及脚注已识别并按范围处理。
- [ ] 中文自然，角色口吻有依据；合理意译、拟声和含糊发音不被误判。
- [ ] 待定译名/草稿占位已解决；有争议或超出范围的内容明确说明。

## 二、结构与机械 QA

- [ ] 默认 1:1 模式：章节集合和非空行数量对应，标题层级、分隔符及插图引用位置一致。经允许拆并段时改查源范围映射，不能用本包脚本判定通过。
- [ ] 假名候选已核对：漏译需修复；允许保留的人名、词语或特殊写法有明确记录。标题也须检查，奥付等原文保留文件显式排除。
- [ ] 术语检查以本作品词表为准；统计计数只是线索，需逐处核对用法，而不是计数相同即可通过。
- [ ] 长度比异常、连续重复或格式标记均作为候选报警；阈值先用小样校准。例如 CN/JP <0.25 或 >3 可提示检查，不作普遍硬门槛。短句、标题、拟声、合法重复和未保留图文须分类处理。
- [ ] 非空行计数与物理行号区分，统计注明是否包含标题、插图、奥付。空章、缺章、额外章节不能作为成功跳过。

从项目工作目录运行，脚本路径替换为实际安装位置：

```sh
python /path/to/lightnovel-trans/scripts/verify_alignment.py work/extracted/volume-jp/chapters work/volume-cn/chapters
python /path/to/lightnovel-trans/scripts/check_kana.py work/volume-cn/chapters --exclude colophon --allow "原文保留的名字"
```

`--exclude` 按文件名或不带扩展名的名字精确匹配。`--separator` 可在结构脚本中重复指定其他独立分隔行。本包两项检查只读；非零退出码表示失败或输入错误，不能忽略。

## 三、EPUB（仅当目标含成品）

- [ ] ZIP/mimetype、container 指向、OPF 元数据/manifest/spine、导航、资源引用和锚点合法；按 EPUB 版本检查，不能只有 XML 可解析。
- [ ] 成品正文、标题、插图顺序与译稿及源映射一致，不能只抽几句证明全卷回写完整。
- [ ] 回写或修订的变化文件与内容均在本次预期范围，未改资源字节一致；自建 EPUB 不套原版字节一致规则。
- [ ] 译文页与保留日文页的语言标记正确，元数据与排版方向符合成品，布局说明随排版更新。
- [ ] 按阅读需求抽查正文、长标题、目录、分隔符、插图、脚注/特殊文字；测完关闭自己启动的服务和页面。浏览器预览不等于 EPUB 阅读器兼容性验证。
- [ ] 若已有 EPUBCheck，运行并记录结果；未运行时不声称全面标准合规。
- [ ] 已知例外逐条说明语义与结构影响，不能把未解释的内容损失列为“正常”。

## 四、汇报

- [ ] 写明全量/抽样范围、实际运行命令及结果、未验证项、发现的问题与交付路径。
- [ ] 审核只给建议；授权修订后给修改与验证对照。只需要译稿或报告时跳过打包。
